# 构建与运行

离线功能展示直接运行根目录 `start_demo.cmd`，或 `python -m runtime.run_board --demo`。新增入口和页面操作见 [主程序演示](主程序演示.md)，不会进入下文的板端正式启动路径。

本目录是正式提交版。所有命令均在本目录执行，开发工具路径通过参数传入。2026-11-03 在用户授权后完成了 RAM 临时上板演示；原自启动镜像未修改。当前板端演示入口、显示修复与实际边界见 [实板演示记录](实板演示记录-20261103.md)。程序、驱动与显示运行记录在上述文档统一列出。

收到包后可先用 Python 标准库核对全部文件：`python tools/verify_delivery.py`；也可用 `--zip <ZIP文件>` 直接核对压缩包及相邻 `.sha256` 文件，不需要安装训练环境。

## 开发依赖

- Python 3.10+，NumPy、OpenCV、PyTorch（训练工具需要；正式运行不需要 PyTorch）。`runtime/requirements.txt` 列出 ARM 数值处理及可选原规则模块的 Python 依赖。
- 兼容 ARMv7 hard-float 的 Linux C/C++ 编译器；Vivado 2018.3 与 Zynq-7020 器件支持。
- 如构建内核模块，需要目标 Linux 的已配置内核源码、对应工具链。不是宿主 Windows 的头文件。
- 字形/光标程序资源已经随包提供，不需要电脑字体服务。预建几何仅为先验。

## 从源码重建模型

```text
python tools/train_models.py --task registration --epochs 100
python tools/train_models.py --task frame --epochs 100
python tools/qat_registration.py
python tools/export_binary.py
```

两个训练命令分开执行，以复现各自的随机种子初始化。训练记录保存宽模型、L1 通道选择、剪枝未微调模型、微调模型、INT8 参数、校准尺度和哈希。配准 QAT 的失败尝试另存，不能只展示成功结果。GPU、库版本和浮点非确定性可能造成数值差异；重新训练后必须重跑后续整数验证。

## 完整硬件工程

```text
python tools/build_combined.py --vivado-bin <Vivado-bin> --work <new-ASCII-combined-build-directory>
```

`resources/factory` 已保存最小 PS 配置和 DVI 源码，`resources/adc_bringup.xdc` 保存原引脚配置。无需旧工程或旧运行目录。当前按功能展示目标构建：图形、AI、AXI、显示搬运实际连接到 PS FCLK1 62.5 MHz；HDMI 继续使用 FCLK0 100 MHz 参考生成 74.25/371.25 MHz，保持 1280×720。ADC 原始采样时钟仍为标称 200 MHz。脚本检查 PS 实际频率和链接后着色器的 16 ns 时钟周期，降低的是实际硬件配置，处理速度与帧率不作实测承诺。脚本中没有编程开发板的命令。ADC配置与时钟约束见配套XDC及硬件记录。

地址：图形 `0x43C00000`，原 GPIO `0x41200000`，AI `0x43C40000/0x40000`，ADC `0x43C80000/0x20000`。本版GPU source tag 是模板值 0；UI 启动参数必须显式传 `--tag 0`，加载图形模块时也须显式指定 `expected_tag=0`。驱动用独立标志区分“没有提供 tag”和“显式传 0”：前者拒绝，后者仍须与硬件值相等。驱动能力、ABI 和 AI 硬件版本仍分别检查。此模板 tag 不提供唯一构建身份，源码哈希清单承担离线构建溯源；运行时显式匹配模板tag，并结合源码与产物哈希定位版本。两份驱动已经在配套实板环境加载。

图形 ABI 仍为 3，原结构大小不变。新增 `GFX3_FEAT_DEPTH`、`GFX3_DEPTH_JOB`、类型 `GFX3_DEPTH`；开启能力时 `gfx3_job.reserved[1]` 是深度 BO 句柄。旧调用保留 0，硬件不写深度；不支持能力时拒绝新标志。原有 UI 图层仍用 `reserved[0]`。

## 内核模块

```text
make -C <configured-target-kernel> M=<absolute-submission>/drivers ARCH=arm CROSS_COMPILE=<prefix> modules
make -C <configured-target-kernel> M=<absolute-submission>/graphics/driver ARCH=arm CROSS_COMPILE=<prefix> modules
```

`drivers/compute.dtsi` 是新增节点片段，两个节点的 `aclk` 均引用 FCLK1（`clkc 16`）。配套设备树为 `drivers/demo-7020.dts` 与已编译的 `bin/demo-7020.dtb`；它保留 FCLK0/FCLK1，使图形和计算设备引用与新硬件一致，计算驱动会持有对应时钟。设备树与本版硬件时钟初始化配套，RAM启动和驱动加载记录见实板演示文档。

用户明确授权后，已在 vm-claude 的独立构建目录完成两份 `.ko` 编译，并取回 `bin/pcb_compute.ko` 与 `bin/pcb_gfx3.ko`。两者为 ELF32 little-endian ARM，vermagic 为 `5.4.0-xilinx-v2020.2 SMP preempt mod_unload modversions ARMv7 p2v8`。构建使用已配置的目标内核及 GCC 9.2.0；日志、内核配置/符号版本指纹、源哈希和模块哈希在 `evidence/kernel`。配套实板的模块加载结果见实板演示记录。

`tools/build_kernel.py` 是显式配置远端构建环境的可选工具，不属于板端运行链；仅传送驱动目录白名单源码、两份已获授权的设备树及公开 Xilinx 基础定义，不携带 SSH 配置或私钥。公开依赖已随包保存并固定 SHA256，构建机无需联网下载。复现形式如下（SSH 配置和工具目录由使用者提供）：

```text
python tools/build_kernel.py --ssh <ssh-executable> --ssh-config <local-ssh-config> --build-host vm-claude --toolbase <configured-toolbase> --remote-work /home/<user>/pcb-submission-build
```

## 板端采集与处理入口

```text
python -m runtime.capture_live --board dcdc --rgb-device /dev/video0 --thermal-device /dev/video1 --output <new-raw-directory>
bin/pcb_adc /dev/pcb_adc <raw-frame.u32>
python -m runtime.run_board --bundle <verified-capture.bundle.json> --reference <normal-reference-RGB> --tag <matching-hardware-tag> --board dcdc
```

相机程序只在 ARM Linux 正式路径运行；设备节点必须由实际系统选择。热像实时记录没有标定时，原始热像页可用，配准和融合保持禁用。ADC 工具读取冻结的完整原始帧；必须按机械实测位置关联三帧，不会默认编造扫描位置或自动运动。

ADC 原型采集前等待 1024 个 200 MHz 时钟，并在一帧后停止时钟/置电源控制为关闭。该等待窗口由数字接口实现，采集配置应结合前端与ADC的工作条件。工具在 MMCM 未锁定时禁用采集；超时不会把旧帧作为新帧，由调用方处理恢复流程。

正式推理默认 `/dev/pcb_ai`，缺失/版本不符/超时均报错或禁用相关功能。`--offline-test` 仅用于明确的离线验证，不会被正式模式自动选择。ARM数值处理环境按 `runtime/requirements.txt` 配置。提交包的 `data/derived` 不参与正式发布包；正式入口使用新目录重新计算。

AOI页加载正常参考RGB后执行对照，配套回归包含原图自比较。该规则模块输出可见外观变化候选。
