## 黑屏原因与修复

初次加载后，板上导出的完整图像正常，但 HDMI 显示器只有顶部一条、下面全黑。扫描缓冲断流计数约每秒增加 30 次。62.5 MHz 配置下同时读取 RGB 与 UI 两层的显示通路未能持续供数。

最终程序默认启用 `--single-plane 1`，把 UI 纳入 PL 的整帧渲染，扫描输出只读取一份完整画面。补帧仍调用 PL CNN；准备好的 RGB 中间帧使用独立纹理和独立显示缓冲，由 PL 绘制并显示，随后继续提交下一张真实渲染帧。真实 RGB、深度、选点 ID 缓冲不被中间帧覆盖，合成图像不进入测量分析输入。

修复后的断流计数保持在历史累计值 23,294，经过旋转、补帧、页面切换及扫描演示后没有继续增加。用户确认显示器已完整显示三维板卡及面板。`--single-plane 0` 保留旧的双层通路供比较，不适用于本次实测的 62.5 MHz 演示配置。

一次补帧准备及显示约需 1.34 s；这证明了功能接通，尚不能称为流畅实时补帧、DLSS 性能或 AI 加速比测试。

## 重现本次板端演示

先临时加载配套 r6 位流、DTB 和驱动，再把程序及经来源校验的显示素材放入 RAM。图形模块必须显式指定 `expected_tag=0`。本记录没有提供写入自启动存储的安装步骤。

```sh
insmod bin/pcb_compute.ko
insmod bin/pcb_gfx3.ko expected_tag=0
sh start_board_demo.sh --display /tmp/pcb-trial/display --state /tmp/pcb-trial/launch-final-r2 --tag 0
```

`--display` 是从原始记录生成的显示素材目录，须含 `generation.json`；本次素材在电脑上重新生成后传到 RAM。`--state` 和显示快照目录限定在 `/tmp`。启动脚本将随包的 CPython 3.7.6 纯 Python 标准库解压到 RAM，补齐原系统缺少的基础模块，使用原有 Python，不安装或修改原系统。标准库来源与许可证随包保留。

界面左侧“扫描演示”可开始、停止和选择结果点。该页明确使用模拟运动、历史原始数据与已核验 RTL 结果回放；本次没有向机械机构发送运动指令。
